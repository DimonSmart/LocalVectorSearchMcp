# 0005.spec-mcp-and-cli

## Intent

The server exposes editable local Markdown-workspace operations and production image-asset operations through official MCP stdio tools, and retains CLI maintenance commands for reindexing and status. Remote ChatGPT access may bridge this same stdio surface through OpenAI Secure MCP Tunnel without adding a remote transport to the server.

## Behavior

Primary mode is MCP over stdio using the official `ModelContextProtocol` SDK. The server registers tools from assembly and does not implement protocol transport, discovery, messages, or schemas manually.

The exposed tools are exactly:

- `kb_reindex`, `kb_status`
- `kb_search`, `kb_read`
- `kb_patch`, `kb_create`, `kb_move`, `kb_delete`
- `kb_list_files`, `kb_outline`
- `kb_save_image`, `kb_list_images`, `kb_load_image`, `kb_delete_image`, `kb_move_image`

No `debug_*` image-transfer tools are part of the production MCP surface.

### Reindex lifecycle

The MCP `kb_reindex(scope, force)` request contract remains valid, but its response lifecycle is asynchronous. The call atomically starts the single active process-local reindex when idle and returns `started: true` plus current operation metadata; when a reindex is already running it returns `started: false` plus the unchanged active operation. A duplicate request does not wait, queue another reindex, change active parameters, or start a second embedding pipeline.

The long-running operation belongs to the host lifecycle rather than the completed MCP request. Client cancellation after acceptance does not cancel it; host shutdown does. `kb_status.indexing` exposes active scope/force/start time and real file progress when known, plus the last completed outcome and final `ReindexResponse` or diagnostic error. Failed or cancelled operations clear the running state and a later request may retry.

The existing `IndexOperationGate` continues to serialize full reindex writes with targeted reconciliation. Independent source/navigation calls are not serialized behind the reindex. `kb_read`, `kb_outline`, and `kb_list_files` operate from current workspace source and remain available during ordinary and forced destructive reindex. `kb_search` operates on committed derived index data; if a forced incompatible rebuild has entered its destructive reset phase, search fails quickly with a controlled rebuild-in-progress message while source/navigation tools remain available.

CLI `--reindex` and `--reindex --force` remain synchronous and return the final `ReindexResponse` before process exit.

CLI options also include `--project-root` (absolute, existing project directory), `--embedding-provider`, `--search-mode`, `--watch-files`, and `--no-watch-files`. An explicit project root overrides `CLAUDE_PROJECT_DIR` and process working directory; `--root` is always the independent, narrower knowledge-base root. The `--status`/MCP `kb_status` response includes effective index mode, embedding provider and model (or `none`), document/chunk counts, synchronization/reindex progress, and manifest compatibility. Project-local .NET tool manifests are discovered by the .NET CLI based on working directory, regardless of `--project-root`; `dnx` or a self-contained executable avoid that manifest lookup.

### Markdown workbench

`kb_read(path, pointer?, maxElements?, maxBytes?)` accepts `document`, an unhashed logical pointer for position-based navigation, a legacy v1 `logical~selfHash` anchor, or a canonical v2 `logical~selfHash~subtreeHash` concrete-element anchor. Omitting `pointer` is equivalent to `pointer = "document"`; an explicitly supplied empty or whitespace pointer is invalid. `document` means the beginning of the whole Markdown document, not the first heading.

Root reads return real source elements in source order, including front matter and content before the first heading. The synthetic empty `Document` element is only an address/container and does not consume limits or appear in returned Markdown. Empty documents return a successful empty slice with `Pointer = "document"`, `NextPointer = null`, and current exact-source `sourceHash`.

`kb_read` loads one current Markdown source revision directly from the workspace. `Markdown`, `Elements`, public anchors, `NextPointer`, and `sourceHash` are all derived from that same loaded revision; the Markdown is never reconstructed from `Elements[].Text` and read does not depend on SQLite, embeddings, or background index completion. Read boundaries preserve container syntax and raw source between semantic elements. Document-root reads begin at source offset zero; non-root reads begin at the source line/container boundary of the resolved first element. When pagination has a `NextPointer`, the current slice ends at the corresponding next read boundary so consecutive slices concatenate without loss or duplication. A terminal slice may extend through EOF.

`maxElements` continues to count semantic elements only. `maxBytes` is evaluated against the UTF-8 byte count of the exact source slice that would actually be returned. Pagination may stop only at semantic/read boundaries; the first indivisible source segment is still returned whole when it alone exceeds the byte limit.

For concrete elements, public `Pointer`, `Elements[].Pointer`, and `NextPointer` values are canonical v2 anchors. `selfHash` covers the exact element span; heading `subtreeHash` covers the full exact section range owned by `replace_section` and `delete_section`, while leaf hashes are equal. A hashed input may relocate to a unique current element only by element kind plus exact `selfHash`; the response returns the resolved current v2 anchor. `subtreeHash` is not a read concurrency barrier: if a heading itself is unchanged, a stale subtree hash may still navigate to the current section content. Unhashed input remains valid for navigation.

`kb_search` retains existing requests and optional `includeGlobs` and `excludeGlobs`. Its `Results[].Pointer`, `FullPointer`, and `ReadHint.Pointer` expose both hashes stored for the indexed chunk-start element, and every `SearchResultItem` also exposes `indexedSourceHash` from that same indexed document revision. Search results may temporarily lag behind current source if reconciliation is pending or failed; clients can compare revision metadata when relevant, while mutation always validates against the current source file.

`kb_outline(path)` returns nested headings with canonical v2 public pointers.

`kb_patch(path, operations)` performs atomic Markdown mutation with element/subtree optimistic concurrency. `expectedSourceHash` is not part of its MCP schema or request DTO. Supported kinds are `replace`, `replace_element`, `replace_fragment`, `replace_section`, `delete_section`, `insert_before`, `insert_after`, and `delete`. `replace`, `replace_element`, `insert_before`, `insert_after`, and `delete` are `Self` operations and require `selfHash`; legacy v1 input remains valid for them. `replace_section` and `delete_section` are `Subtree` operations and require canonical v2 heading input with `subtreeHash`. The unhashed `document` pointer remains valid for `insert_before` and `insert_after` only.

`replace_element` replaces exactly one editable Markdown element; its replacement must contain exactly one editable element. For a heading it replaces only that heading and must preserve its level. Legacy `replace` remains as a deprecated alias of `replace_element`; existing correct single-element calls stay compatible, while multi-element replacement through `replace` is intentionally rejected.

`replace_section` is the explicit operation for rewriting a chapter or section. Its target must resolve to a heading. A level-N heading owns all source through nested headings until the next heading with level <= N, exclusive, or EOF. The replacement must start with a heading of the same level and all later headings must be deeper. The operation is one atomic server-side patch operation, not a client-side delete/insert sequence.

`delete_section` is the symmetric destructive section operation. It requires the same canonical v2 heading pointer and owned source range as `replace_section`, validates `subtreeHash` after safe relocation, accepts no `markdown`, and atomically removes the heading plus its complete section subtree. Plain `delete` remains Self-scoped and removes only one Markdown element, so deleting a heading with `delete` preserves its section body.

All patch anchors are resolved against one current source revision before source construction. Direct pointer-plus-`selfHash` match wins. Otherwise exact kind-plus-`selfHash` relocation must yield exactly one candidate. For `Subtree`, the expected `subtreeHash` is compared only after resolution. Section boundaries and subtree hashing use the same owned-source-range rule. Missing, changed, stale-subtree, missing-subtree-hash, ambiguous, duplicate-resolved, overlapping, or contradictory targets reject the entire patch.

A full-document `SourceHash` remains an internal guard for the read-to-atomic-write window of each patch attempt. If an external process edits the file during that window, the server performs a bounded retry against the newest source and re-resolves the original client anchors, including the appropriate self/subtree validation. This internal mechanism is not exposed as a `kb_patch` client token.

Expected patch/domain failures are returned as MCP tool errors with actionable messages. Operations that require an existing Markdown source distinguish invalid/security-sensitive paths, a missing source document, a missing or stale semantic target, whole-document source conflicts, and unexpected filesystem/internal failures. A missing source document is represented by the shared `DocumentNotFound` domain condition and returned as a normal MCP tool execution error (`CallToolResult.IsError = true`) with `Document '<path>' was not found.`; it is not converted into a semantic-pointer error or a JSON-RPC protocol error. `kb_create` is excluded because a missing target is its normal precondition. Unexpected internal exceptions retain the SDK's generic client-facing handling.

`kb_read` continues to return `sourceHash` because `kb_move` and `kb_delete` retain their whole-file `expectedSourceHash` contract. `kb_create` never overwrites. Mutation responses distinguish a committed source revision with pending or failed index synchronization from an already synchronized index; a committed source mutation is successful even while targeted reconciliation continues in the background. Markdown mutation tools return a controlled error when writes are disabled.

`kb_list_files` optionally filters by path prefix and include glob and returns stable entries containing relative path, kind (`markdown` or `asset`), size, and last-write time.

### Image assets

Images are non-indexed binary assets. All five image tools use safe relative paths under `knowledgeBase.root` with one shared reparse/traversal/no-overwrite policy. `images/` is the default save directory only. Supported signatures and extensions are PNG, JPEG (.jpg/.jpeg), GIF and WebP; SVG is not supported. Image tools never read, modify, index, or synchronize Markdown.

`kb_save_image(file, fileName?, altText?, directory?, documentPath?)` keeps `_meta["openai/fileParams"] = ["file"]`, requires `file.download_url` and `file.file_id`, and streams HTTPS bytes with current SSRF, redirect, MIME, signature, and 25 MiB enforcement. `directory` is a workspace-relative folder (`images` by default, `.` = root). `documentPath` is an optional .md workspace path used only to construct a relative Markdown destination. Validate these and the explicit basename before downloading; the Markdown document need not exist. Save uses a same-filesystem temporary file and atomic no-overwrite publication with numeric suffixes. Response fields remain `path`, `mimeType`, `bytes`, `sha256`, and `markdown`. URI-special characters are escaped; no Markdown is changed.

`kb_list_images(cursor?, pageSize?)` recursively scans the entire root, ignoring Markdown include/exclude, skips links/reparse points, and sorts OrdinalIgnoreCase then Ordinal. Cursor version is `v2` (old `v1` invalid). Default page size is 50, maximum 200. It returns an empty page if there are no assets, even when `images/` is absent. It does not open files to check signatures.

`kb_load_image(path)` works with any safe image file under root, even in read-only mode. It checks signature, extension, size, and SHA-256 and returns an MCP `ImageContentBlock` first with a JSON metadata text block second. It must not expose `StructuredContent` or `OutputSchemaType`, since wrappers may hide the image block.

`kb_delete_image(path)` deletes one binary image anywhere within root without looking up references or deleting parent directories. `kb_move_image(request)` moves only a source image to an available supported-format target, subject to optional valid 64-hex `expectedSha256`. The legacy nullable `updateReferences` is compatibility-only: absent/false means binary move; true throws a controlled MCP error before mutations. The move response has only `previousPath`, `path`, `sha256`. Neither move nor delete touches .md or schedules indexing. The source is revalidated before an atomic no-overwrite move; no copy-delete fallback is allowed.

References are ordinary Markdown strings changed by `kb_patch(replace_fragment)`. Save→patch, move→patch, and save→patch→optional delete are separate calls without a shared transaction. The client rereads anchors and repairs any failed patch after a successful asset action. An image reference need not resolve to a current asset.

### Layering and CLI

Knowledge-base and image tool classes are thin wrappers over transport-independent application services and contain no SQL, embedding calls, parsing/chunking implementation, or direct filesystem mutation. OpenAI-specific file-parameter DTO/conversion and MCP `CallToolResult`/`ImageContentBlock` construction remain in Server. Core image contracts do not depend on MCP or OpenAI types.

CLI maintenance mode preserves `--reindex`, `--reindex --force`, and `--status`, existing configuration options, configless defaults, stdout/stderr separation, and published artifact behavior.

ChatGPT remote access is supported through OpenAI Secure MCP Tunnel as an external stdio bridge. Direct remote HTTP MCP hosting remains excluded. Stdout in MCP mode is reserved exclusively for protocol traffic.

## Acceptance Criteria

- MCP exposes exactly the fifteen named tools above; no diagnostic `debug_*` image tools are exposed.
- Existing valid `kb_search`, `kb_status`, `kb_reindex`, and CLI requests remain valid; MCP `kb_reindex` returns start/current state while CLI reindex remains synchronous.
- At most one MCP full reindex runs at a time; duplicate calls return immediately without creating a second pipeline.
- `kb_status.indexing` exposes active progress and the last success/failure/cancellation result and remains callable while reindex is running.
- MCP request cancellation after acceptance does not own the background reindex; host shutdown cancellation does.
- Existing valid `kb_read`, `kb_move`, `kb_delete`, listing, outline, semantic-anchor, and single-element `kb_patch kind=replace` requests remain compatible; unsafe multi-element `replace` is intentionally rejected and must use `replace_section` or other explicit operations.
- `kb_read.Markdown` preserves the exact current source representation inside its page window, including list markers, indentation, line endings, blank lines, inline syntax, and raw non-element Markdown; pagination and byte limits use those exact source boundaries.
- The real `kb_patch` schema exposes `replace_fragment` with `oldMarkdown` and all existing operations; the patch DTO does not expose `expectedSourceHash`.
- The `kb_patch` tool description explicitly distinguishes element replacement/deletion from section replacement/deletion, explains that heading `delete` preserves the section body, and identifies `replace` as the deprecated alias of `replace_element`.
- `kb_save_image` preserves the OpenAI fileParams metadata and adds optional `directory` and `documentPath` parameters.
- Save/delete/move are rejected when writes are disabled; list/load remain available.
- Save publishes only validated supported files inside the requested in-root directory with a same-directory temporary file, SHA-256, and no-overwrite move.
- Explicit invalid names or mismatched extensions are controlled errors; unsafe external file-name metadata cannot cause path traversal.
- `kb_list_images` recursively enumerates supported image extensions, skips linked/reparse paths, uses stable ordering and opaque versioned cursor pagination, and returns `nextCursor=null` on the final page.
- `kb_load_image` validates path, size, signature, and extension/signature agreement and returns the real MCP `ImageContentBlock` as its first content block plus JSON text metadata as the second block; it does not use `StructuredContent`.
- `kb_delete_image` deletes exactly one valid image file anywhere under the root, including referenced files, without changing Markdown.
- Images are visible via `kb_list_files` as non-indexed assets; no image operation updates Markdown or schedules reconciliation.
- `kb_move_image` is binary only, rejects `updateReferences=true`, accepts optional valid SHA-256, preserves no-overwrite, and responds with `previousPath`, `path`, `sha256`.
- Application image services remain reusable by a future transport without depending on MCP/stdin/stdout/OpenAI DTOs.
- The process-level stdio integration initializes, lists exactly fifteen tools, validates schemas/metadata, returns a real image block, and shuts down cleanly.

- Unit-test image format detection, MIME agreement, explicit/fallback filename policy, Markdown reference escaping, cursor encode/decode and ordering, and image path policy.
- Integration-test writes-disabled behavior, successful PNG save, collision/concurrent save, size limits, recursive listing/pagination, load validation/output, delete semantics, `kb_list_files` asset visibility, and index isolation.
- Test downloader SSRF policy and redirect validation without external network dependence.
- Verify through real `tools/list` that the five image tools exist, diagnostic tools do not, `kb_save_image` publishes the OpenAI file-parameter metadata/schema, `kb_move_image` publishes its structured request/response schema, structured output schemas remain enabled for the image tools where applicable except the deliberately content-first `kb_load_image`, and `kb_patch` exposes the complete patch-kind enum plus the element/section replacement/deletion description without `expectedSourceHash`.
- Through the real stdio client, verify a controlled slow `kb_reindex` returns before embeddings complete, `kb_status`/`kb_read`/`kb_list_files`/`kb_outline` remain responsive, `kb_search` returns the controlled destructive-rebuild error when applicable, a duplicate reindex returns `started: false`, and final state appears in `kb_status.indexing.last`.
- Through the real stdio client, verify `kb_load_image` returns an actual `ImageContentBlock`.
- Through the real stdio client, verify expected image domain/security failures return `IsError = true` with actionable text.
- Integration-test `kb_move_image` root containment, reparse-point rejection, format compatibility, expected SHA-256, nested relative Markdown links, multiple references/documents, include/exclude scope, updateReferences=false, bounded concurrency retry, atomic rollback, no-overwrite behavior, and targeted reconciliation.
- Verify `kb_move` and `kb_delete` still expose and enforce whole-file hashes.
- Run existing CLI, publish, packaging, and tunnel verification.
