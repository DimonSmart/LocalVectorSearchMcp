# 0005.spec-mcp-and-cli

## Intent

The server exposes editable local Markdown-workspace operations and production image-asset operations through official MCP stdio tools, and retains CLI maintenance commands for reindexing and status. Remote ChatGPT access may bridge this same stdio surface through OpenAI Secure MCP Tunnel without adding a remote transport to the server.

## Behavior

Primary mode is MCP over stdio using the official `ModelContextProtocol` SDK. The server registers tools from assembly and does not implement protocol transport, discovery, messages, or schemas manually.

The exposed tools are exactly:

- `kb_reindex`, `kb_status`
- `kb_search`, `kb_read`
- `kb_patch`, `kb_create`, `kb_move`, `kb_delete`
- `kb_list_files`, `kb_outline`
- `kb_save_image`, `kb_list_images`, `kb_load_image`, `kb_delete_image`

No `debug_*` image-transfer tools are part of the production MCP surface.

### Reindex lifecycle

The MCP `kb_reindex(scope, force)` request contract remains valid, but its response lifecycle is asynchronous. The call atomically starts the single active process-local reindex when idle and returns `started: true` plus current operation metadata; when a reindex is already running it returns `started: false` plus the unchanged active operation. A duplicate request does not wait, queue another reindex, change active parameters, or start a second embedding pipeline.

The long-running operation belongs to the host lifecycle rather than the completed MCP request. Client cancellation after acceptance does not cancel it; host shutdown does. `kb_status.indexing` exposes active scope/force/start time and real file progress when known, plus the last completed outcome and final `ReindexResponse` or diagnostic error. Failed or cancelled operations clear the running state and a later request may retry.

The existing `IndexOperationGate` continues to serialize full reindex writes with targeted reconciliation. Independent source/navigation calls are not serialized behind the reindex. During ordinary reindex, `kb_read` and `kb_search` use currently committed per-document index data. If a forced incompatible rebuild has entered its destructive reset phase, those two index-dependent tools fail quickly with a controlled rebuild-in-progress message; `kb_status`, `kb_list_files`, and `kb_outline` remain available.

CLI `--reindex` and `--reindex --force` remain synchronous and return the final `ReindexResponse` before process exit.

### Markdown workbench

`kb_read(path, pointer?, maxElements?, maxBytes?)` accepts `document`, an unhashed logical pointer for position-based navigation, a legacy v1 `logical~selfHash` anchor, or a canonical v2 `logical~selfHash~subtreeHash` concrete-element anchor. Omitting `pointer` is equivalent to `pointer = "document"`; an explicitly supplied empty or whitespace pointer is invalid. `document` means the beginning of the whole Markdown document, not the first heading.

Root reads return real source elements in source order, including front matter and content before the first heading. The synthetic empty `Document` element is only an address/container and does not consume limits or appear in returned Markdown. Empty documents return a successful empty slice with `Pointer = "document"`, `NextPointer = null`, and current exact-source `sourceHash`.

`kb_read.Markdown` is a continuous editable slice taken directly from `documents.markdown` for the same indexed revision as `Elements`, public anchors, and `sourceHash`; it is never reconstructed from `Elements[].Text` or reread from the current filesystem. Read boundaries preserve container syntax and raw source between semantic elements. Document-root reads begin at source offset zero; non-root reads begin at the source line/container boundary of the resolved first element. When pagination has a `NextPointer`, the current slice ends at the corresponding next read boundary so consecutive slices concatenate without loss or duplication. A terminal slice may extend through EOF.

`maxElements` continues to count semantic elements only. `maxBytes` is evaluated against the UTF-8 byte count of the exact source slice that would actually be returned. Pagination may stop only at semantic/read boundaries; the first indivisible source segment is still returned whole when it alone exceeds the byte limit.

For concrete elements, public `Pointer`, `Elements[].Pointer`, and `NextPointer` values are canonical v2 anchors. `selfHash` covers the exact element span; heading `subtreeHash` covers the full exact section range owned by `replace_section`, while leaf hashes are equal. A hashed input may relocate to a unique current element only by element kind plus exact `selfHash`; the response returns the resolved current v2 anchor. Unhashed input remains valid for navigation.

`kb_search` retains existing requests and optional `includeGlobs` and `excludeGlobs`. Its `Results[].Pointer`, `FullPointer`, and `ReadHint.Pointer` expose both hashes stored for the indexed chunk-start element, so one anchor always belongs to one indexed revision. Search results may become stale if the source changes before the index reconciles; mutation always validates against the current source file.

`kb_outline(path)` returns nested headings with canonical v2 public pointers.

`kb_patch(path, operations)` performs atomic Markdown mutation with element/subtree optimistic concurrency. `expectedSourceHash` is not part of its MCP schema or request DTO. Supported kinds are `replace`, `replace_element`, `replace_section`, `insert_before`, `insert_after`, and `delete`. `replace`, `replace_element`, `insert_before`, `insert_after`, and `delete` are `Self` operations and require `selfHash`; legacy v1 input remains valid for them. `replace_section` is a `Subtree` operation and requires canonical v2 input with `subtreeHash`. The unhashed `document` pointer remains valid for `insert_before` and `insert_after` only.

`replace_element` replaces exactly one editable Markdown element; its replacement must contain exactly one editable element. For a heading it replaces only that heading and must preserve its level. Legacy `replace` remains as a deprecated alias of `replace_element`; existing correct single-element calls stay compatible, while multi-element replacement through `replace` is intentionally rejected.

`replace_section` is the explicit operation for rewriting a chapter or section. Its target must resolve to a heading. A level-N heading owns all source through nested headings until the next heading with level <= N, exclusive, or EOF. The replacement must start with a heading of the same level and all later headings must be deeper. The operation is one atomic server-side patch operation, not a client-side delete/insert sequence.

All patch anchors are resolved against one current source revision before source construction. Direct pointer-plus-`selfHash` match wins. Otherwise exact kind-plus-`selfHash` relocation must yield exactly one candidate. For `Subtree`, the expected `subtreeHash` is compared only after resolution. Section boundaries and subtree hashing use the same owned-source-range rule. Missing, changed, stale-subtree, missing-subtree-hash, ambiguous, duplicate-resolved, overlapping, or contradictory targets reject the entire patch.

A full-document `SourceHash` remains an internal guard for the read-to-atomic-write window of each patch attempt. If an external process edits the file during that window, the server performs a bounded retry against the newest source and re-resolves the original client anchors, including the appropriate self/subtree validation. This internal mechanism is not exposed as a `kb_patch` client token.

Expected patch/domain failures are returned as MCP tool errors with actionable messages. Unexpected internal exceptions retain the SDK's generic client-facing handling.

`kb_read` continues to return `sourceHash` because `kb_move` and `kb_delete` retain their whole-file `expectedSourceHash` contract. `kb_create` never overwrites. Mutation responses distinguish a committed source revision with pending or failed index synchronization from an already synchronized index; a committed source mutation is successful even while targeted reconciliation continues in the background. Markdown mutation tools return a controlled error when writes are disabled.

`kb_list_files` optionally filters by path prefix and include glob and returns stable entries containing relative path, kind (`markdown` or `asset`), size, and last-write time.

### Image assets

Images are ordinary workspace assets under `<knowledgeBase.root>/images/` and are never part of the semantic index. The first production image surface supports PNG, JPEG, WebP, and GIF. SVG and arbitrary binary files are excluded.

`kb_save_image(file, fileName?, altText?)` declares the top-level `file` field through `_meta["openai/fileParams"] = ["file"]`. The OpenAI file object requires `download_url` and `file_id`; `mime_type` and `file_name` are optional. The tool requires `knowledgeBase.allowWrites=true`.

The save flow securely streams the temporary HTTPS download into a same-filesystem temporary file, enforces the 25 MiB limit from headers and actual bytes, computes SHA-256 while streaming, determines the actual image format from magic bytes, and atomically moves the validated file to its final no-overwrite destination. PNG, JPEG, WebP, GIF87a, and GIF89a signatures are recognized. Declared known image MIME that contradicts the detected signature is rejected; missing/generic MIME does not prevent a valid signature from being accepted.

An explicit `fileName` is user intent: it must be a portable basename, cannot contain path components/traversal/control characters or Windows reserved device names, cannot end in dot/space, and is rejected rather than silently sanitized when invalid. Its extension must agree with the detected format; a missing extension is added. JPEG accepts `.jpg` and `.jpeg` and generated JPEG names use `.jpg`. Without explicit `fileName`, a safe basename/stem may be taken from external `file.file_name`; unsafe metadata falls back to a generated collision-safe name.

Save writes directly into `images/`; the first version does not select a destination subdirectory. Existing files are never overwritten. Collisions use deterministic numeric suffixes such as `foo.png`, `foo-2.png`, `foo-3.png`, with the final no-overwrite move acting as the race-safe authority.

The structured save response contains project-relative `path`, canonical detected `mimeType`, byte count, lowercase SHA-256, and a ready-to-use Markdown image reference. Alt text escapes backslash and brackets and normalizes line breaks. Paths that require it use a CommonMark-compatible angle-bracket destination.

`kb_list_images(cursor?, pageSize?)` is read-only, recursively enumerates supported image extensions under `images/`, skips links/reparse points, and does not validate every file signature. Missing `images/` returns an empty page. Default page size is 50; valid range is 1..200. Ordering matches workspace listing: ordinal-ignore-case followed by ordinal tie-breaker. Pagination uses an opaque versioned cursor representing the last relative path; malformed or unsupported cursors are controlled errors and deletion of the cursor item between requests does not invalidate the next-page position.

List items contain project-relative `path`, canonical MIME inferred from extension, byte count, and UTC last-write time.

`kb_load_image(path)` is read-only and accepts only files under `images/`, including nested paths created by external tools. It enforces the 25 MiB limit, re-detects the image format from signature, rejects unsupported data and extension/signature mismatch, computes SHA-256, returns structured metadata, and includes the real image bytes as a standard MCP `ImageContentBlock` with canonical MIME.

`kb_delete_image(path)` requires `knowledgeBase.allowWrites=true`, accepts only supported image-file paths under `images/` including nested paths, rejects directories and missing files, deletes only the named file, and does not remove now-empty parent directories.

Save/delete/list/load do not trigger Markdown index synchronization, FTS updates, vector chunk creation, or embeddings. Saved images appear naturally through `kb_list_files` as `asset`; deleted images disappear from it.

### Layering and CLI

Knowledge-base and image tool classes are thin wrappers over transport-independent application services and contain no SQL, embedding calls, parsing/chunking implementation, or direct filesystem mutation. OpenAI-specific file-parameter DTO/conversion and MCP `CallToolResult`/`ImageContentBlock` construction remain in Server. Core image contracts do not depend on MCP or OpenAI types.

CLI maintenance mode preserves `--reindex`, `--reindex --force`, and `--status`, existing configuration options, configless defaults, stdout/stderr separation, and published artifact behavior.

ChatGPT remote access is supported through OpenAI Secure MCP Tunnel as an external stdio bridge. Direct remote HTTP MCP hosting remains excluded. Stdout in MCP mode is reserved exclusively for protocol traffic.

## Acceptance Criteria

- MCP exposes exactly the fourteen named tools above; no diagnostic `debug_*` image tools are exposed.
- Existing valid `kb_search`, `kb_status`, `kb_reindex`, and CLI requests remain valid; MCP `kb_reindex` returns start/current state while CLI reindex remains synchronous.
- At most one MCP full reindex runs at a time; duplicate calls return immediately without creating a second pipeline.
- `kb_status.indexing` exposes active progress and the last success/failure/cancellation result and remains callable while reindex is running.
- MCP request cancellation after acceptance does not own the background reindex; host shutdown cancellation does.
- Existing valid `kb_read`, `kb_move`, `kb_delete`, listing, outline, semantic-anchor, and single-element `kb_patch kind=replace` requests remain compatible; unsafe multi-element `replace` is intentionally rejected and must use `replace_section` or other explicit operations.
- `kb_read.Markdown` preserves the exact indexed source representation inside its page window, including list markers, indentation, line endings, blank lines, inline syntax, and raw non-element Markdown; pagination and byte limits use those exact source boundaries.
- The real `kb_patch` schema exposes `replace`, `replace_element`, `replace_section`, `insert_before`, `insert_after`, and `delete`, and does not expose `expectedSourceHash`.
- The `kb_patch` tool description explicitly distinguishes element replacement from section replacement and identifies `replace` as the deprecated alias of `replace_element`.
- `kb_save_image` publishes `_meta["openai/fileParams"] = ["file"]`, requires `file.download_url` and `file.file_id`, and exposes optional `mime_type`, `file_name`, `fileName`, and `altText`.
- Save/delete are rejected when writes are disabled; list/load remain available.
- Supported image content is saved only under `images/`, with signature validation, canonical MIME, 25 MiB streamed limit, same-directory temporary file, SHA-256, and race-safe atomic no-overwrite move.
- Explicit invalid names or mismatched extensions are controlled errors; unsafe external file-name metadata cannot cause path traversal.
- `kb_list_images` recursively enumerates supported image extensions, skips linked/reparse paths, uses stable ordering and opaque versioned cursor pagination, and returns `nextCursor=null` on the final page.
- `kb_load_image` validates path, size, signature, and extension/signature agreement and returns a real MCP `ImageContentBlock` plus structured metadata.
- `kb_delete_image` deletes only supported image files under `images/` and does not delete directories.
- Images are visible through `kb_list_files` as `asset` and never enter the semantic index or embedding pipeline.
- Application image services remain reusable by a future transport without depending on MCP/stdin/stdout/OpenAI DTOs.
- The process-level stdio integration initializes, lists exactly fourteen tools, validates schemas/metadata, returns a real image block, and shuts down cleanly.

## Verification

- Unit-test image format detection, MIME agreement, explicit/fallback filename policy, Markdown reference escaping, cursor encode/decode and ordering, and image path policy.
- Integration-test writes-disabled behavior, successful PNG save, collision/concurrent save, size limits, recursive listing/pagination, load validation/output, delete semantics, `kb_list_files` asset visibility, and index isolation.
- Test downloader SSRF policy and redirect validation without external network dependence.
- Verify through real `tools/list` that the four image tools exist, diagnostic tools do not, `kb_save_image` publishes the OpenAI file-parameter metadata/schema, all new tools expose structured output schemas where applicable, and `kb_patch` exposes the complete patch-kind enum plus the element/section replacement description without `expectedSourceHash`.
- Through the real stdio client, verify a controlled slow `kb_reindex` returns before embeddings complete, `kb_status`/`kb_list_files`/`kb_outline` remain responsive, a duplicate reindex returns `started: false`, and final state appears in `kb_status.indexing.last`.
- Through the real stdio client, verify `kb_load_image` returns an actual `ImageContentBlock`.
- Through the real stdio client, verify expected image domain/security failures return `IsError = true` with actionable text.
- Verify `kb_move` and `kb_delete` still expose and enforce whole-file hashes.
- Run existing CLI, publish, packaging, and tunnel verification.
