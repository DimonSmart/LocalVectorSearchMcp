# 0005.spec-mcp-and-cli

## Intent

The server exposes editable local Markdown-workspace operations through official MCP stdio tools and retains CLI maintenance commands for reindexing and status. Remote ChatGPT access may bridge this same stdio surface through OpenAI Secure MCP Tunnel without adding a remote transport to the server.

## Behavior

Primary mode is MCP over stdio using the official `ModelContextProtocol` SDK. The server registers tools from assembly and does not implement protocol transport, discovery, messages, or schemas manually.

The exposed tools are exactly:

- `kb_reindex`, `kb_status`
- `kb_search`, `kb_read`
- `kb_patch`, `kb_create`, `kb_move`, `kb_delete`
- `kb_list_files`, `kb_outline`

`kb_read(path, pointer?, maxElements?, maxBytes?)` accepts `document`, an unhashed logical pointer for position-based navigation, or a fingerprinted concrete-element anchor. Omitting `pointer` is equivalent to `pointer = "document"`; an explicitly supplied empty or whitespace pointer is invalid. `document` means the beginning of the whole Markdown document, not the first heading.

Root reads return real source elements in source order, including front matter and content before the first heading. The synthetic empty `Document` element is only an address/container and does not consume limits or appear in returned Markdown. Empty documents return a successful empty slice with `Pointer = "document"`, `NextPointer = null`, and current exact-source `sourceHash`.

For concrete elements, public `Pointer`, `Elements[].Pointer`, and `NextPointer` values are canonical fingerprinted anchors. A fingerprinted input may relocate to a unique current element with the same element kind and exact fingerprint; the response returns the resolved current anchor. Unhashed input remains valid for navigation.

`kb_search` retains existing requests and optional `includeGlobs` and `excludeGlobs`. Its `Results[].Pointer`, `FullPointer`, and `ReadHint.Pointer` expose the fingerprint of the indexed chunk-start element. Search results may become stale if the source changes before the index reconciles; mutation always validates against the current source file.

`kb_outline(path)` returns nested headings with fingerprinted public pointers.

`kb_patch(path, operations)` performs atomic element-level optimistic concurrency. `expectedSourceHash` is not part of its MCP schema or request DTO. Concrete `replace`, `insert_before`, `insert_after`, and `delete` operations require fingerprinted semantic anchors. The unhashed `document` pointer remains valid for `insert_before` and `insert_after` only.

All patch anchors are resolved against one current source revision before source construction. Direct pointer-plus-fingerprint match wins. Otherwise exact kind-plus-fingerprint relocation must yield exactly one candidate. Missing, changed, ambiguous, duplicate-resolved, overlapping, or contradictory targets reject the entire patch.

A full-document `SourceHash` remains an internal guard for the read-to-atomic-write window of each patch attempt. If an external process edits the file during that window, the server performs a bounded retry against the newest source. This internal mechanism is not exposed as a `kb_patch` client token.

Expected patch/domain failures are returned as MCP tool errors with actionable messages, including missing fingerprints, invalid fingerprint syntax, stale or ambiguous anchors, and a document that keeps changing. Unexpected internal exceptions retain the SDK's generic client-facing handling.

`kb_read` continues to return `sourceHash` because `kb_move` and `kb_delete` retain their whole-file `expectedSourceHash` contract. `kb_create` never overwrites. Mutation responses distinguish complete success from source-written/index-update-failed state. Mutation tools return a controlled error when writes are disabled.

`kb_list_files` optionally filters by path prefix and include glob and returns stable entries containing relative path, kind (`markdown` or `asset`), size, and last-write time.

Tool classes are thin wrappers over transport-independent application services and contain no SQL, embedding calls, parsing/chunking implementation, or direct filesystem mutation. Outputs are simple serializable DTOs with no knowledge-base selector.

CLI maintenance mode preserves `--reindex`, `--reindex --force`, and `--status`, existing configuration options, configless defaults, stdout/stderr separation, and published artifact behavior.

ChatGPT remote access is supported through OpenAI Secure MCP Tunnel as an external stdio bridge. Direct remote HTTP MCP hosting remains excluded. Stdout in MCP mode is reserved exclusively for protocol traffic.

## Acceptance Criteria

- MCP exposes the ten named tools through the official SDK.
- Existing valid `kb_search`, `kb_status`, `kb_reindex`, and CLI requests remain valid.
- `kb_read` accepts optional pointer, defaults to `document`, returns exact `sourceHash`, and returns fingerprinted concrete-element anchors.
- Unhashed concrete pointers remain valid for `kb_read` navigation.
- Fingerprinted `kb_read` can relocate one uniquely identifiable structurally shifted element.
- Search and outline return canonical fingerprinted public pointers without changing stored logical pointer identity.
- `kb_patch` exposes `path` and `operations`, with no `expectedSourceHash`.
- Concrete patch operations require fingerprints; `document` remains unhashed for boundary insertion.
- Patch supports replace, insert-before, insert-after, delete, and atomic multi-operation validation.
- Unrelated human edits do not invalidate otherwise valid element anchors.
- Changed/deleted targets and ambiguous relocations return controlled tool errors.
- `kb_move` and `kb_delete` still require `expectedSourceHash`.
- Create/move/delete enforce write configuration, Markdown paths, containment, expected hashes where applicable, and no-overwrite semantics.
- The next request observes each successful mutation's new index state.
- Search against an empty index returns a controlled MCP tool error directing the caller to `kb_reindex`.
- File listing includes assets without indexing them.
- Application services remain reusable by a future transport without depending on MCP/stdin/stdout.
- Process-level stdio integration still initializes, lists exactly the ten tools, and shuts down cleanly.

## Verification

- Unit-test fingerprint exactness, anchor parsing/resolution, enum serialization, scope parsing, conflict errors, and response shapes.
- Integration-test root read, public fingerprinted read pointers, pagination, relocation, search pointers, outline pointers, patch operations, unrelated edits, changed/deleted targets, duplicate candidates, atomic multi-operation patches, file mutations, and disabled writes.
- Verify through real `tools/list` schema that `kb_patch` does not expose `expectedSourceHash` and that `operations[].kind` is exactly `replace`, `insert_before`, `insert_after`, and `delete`.
- Through the real stdio client, verify expected `kb_patch` domain failures return `IsError = true` with actionable text.
- Verify `kb_move` and `kb_delete` still expose and enforce whole-file hashes.
- Run existing CLI, publish, packaging, and tunnel verification.
