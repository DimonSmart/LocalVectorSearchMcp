# 0005.spec-mcp-and-cli

## Intent

The server exposes editable local Markdown-workspace operations through official MCP stdio tools and retains CLI maintenance commands for reindexing and status. Remote ChatGPT access may bridge this same stdio surface through OpenAI Secure MCP Tunnel without adding a remote transport to the server.

## Behavior

Primary mode is MCP over stdio using the official `ModelContextProtocol` SDK. The server registers tools from assembly and does not implement protocol transport, discovery, messages, or schemas manually.

The exposed tools are exactly:

- `kb_reindex`, `kb_status`
- `kb_search`, `kb_read`
- `kb_patch`, `kb_create`, `kb_move`, `kb_delete`
- `kb_list_files`, `kb_outline`

`kb_read(path, pointer?, maxElements?, maxBytes?)` remains backward-compatible and adds an explicit public document-root contract. Omitting `pointer` is equivalent to `pointer = "document"`; an explicitly supplied empty or whitespace pointer is still invalid. `document` means the beginning of the whole Markdown document, not the first heading. Root reads return real source elements in source order, including front matter and content before the first heading, while the synthetic empty `Document` element is only an address/container and does not consume `maxElements` or `maxBytes` and is not added to returned Markdown. Empty documents return a successful empty slice with `Pointer = "document"`, `NextPointer = null`, and the current exact-source `sourceHash`. Pagination from the root uses the same limits as ordinary reads; when more content exists, `nextPointer` is the first not-yet-returned real element and continuation remains inclusive for ordinary element pointers. `kb_search` retains existing requests and adds optional `includeGlobs` and `excludeGlobs`.

`kb_patch(path, expectedSourceHash, operations)` performs atomic revision-checked semantic operations. `kb_patch.operations[].kind` is a closed string enum with wire values `replace`, `insert_before`, `insert_after`, and `delete`. Expected mutation/domain failures are returned as MCP tool errors with actionable messages; unexpected internal exceptions retain the SDK's generic client-facing error handling. `kb_move` and `kb_delete` also require the expected source hash. `kb_create` never overwrites. Mutation responses distinguish complete success from source-written/index-update-failed state. Stale revisions produce a controlled conflict directing the client to read and retry. Mutation tools return a controlled error when writes are disabled.

`kb_list_files` optionally filters by path prefix and include glob and returns stable entries containing relative path, kind (`markdown` or `asset`), size, and last-write time. `kb_outline(path)` cheaply parses one Markdown source into nested heading entries with pointers, levels, and titles.

Tool classes are thin wrappers over transport-independent application services and contain no SQL, embedding calls, parsing/chunking implementation, or direct filesystem mutation. Tool inputs validate required values, paths, pointers, operation conflicts, scopes, and bounds. Outputs are simple serializable DTOs with no knowledge-base selector.

CLI maintenance mode preserves `--reindex`, `--reindex --force`, and `--status`, existing configuration options, configless defaults, stdout/stderr separation, and published artifact behavior.

ChatGPT remote access is supported through OpenAI Secure MCP Tunnel as an external stdio bridge. `tunnel-client` may launch `local-vector-search-mcp --config <absolute-path>` as its local child process. Tunnel credentials, remote connectivity, runtime lifecycle, and health/readiness belong to `tunnel-client`; they are not LocalVectorSearchMcp configuration or MCP tools.

For tunnel deployments, documentation requires explicit absolute `--config`, `knowledgeBase.root`, and `storage.path` values because the child process must not depend on the tunnel runtime's current directory. `knowledgeBase.allowWrites` remains the application-level write gate and defaults to false. Tunnel-specific OAuth scopes do not duplicate it.

Direct remote HTTP MCP hosting remains excluded. The server does not add ASP.NET Core, Kestrel, Streamable HTTP/SSE hosting, OAuth/OIDC/JWT validation, CORS, host validation, reverse-proxy configuration, HTTP health endpoints, or a custom tunnel protocol client.

Stdout in MCP mode is reserved exclusively for protocol traffic. Logs, warnings, diagnostics, startup messages, and errors go to stderr. The server must remain suitable for ownership by a stdio parent process: MCP initialization, tool discovery, tool calls, and shutdown after stdio closure must not require a daemon/service wrapper.

## Acceptance Criteria

- MCP exposes the ten named tools through the official SDK and no manual protocol implementation.
- Existing valid `kb_search`, `kb_read`, `kb_status`, `kb_reindex`, and CLI requests remain valid.
- `kb_read` accepts an optional pointer, defaults it to `document`, exposes that behavior through MCP tool discovery, and returns exact `sourceHash`; stale mutation hashes never overwrite source.
- `kb_read(path, "document")` starts at the first real source element, preserves root-level/front-matter content, supports empty documents, and paginates without counting the synthetic `Document` element.
- Patch supports replace, insert-before, insert-after, delete, and atomic multi-operation validation; its MCP schema exposes exactly the four corresponding string wire values.
- Create/move/delete enforce write configuration, Markdown paths, containment, expected hashes where applicable, and no-overwrite semantics.
- The next request observes each successful mutation's new index state.
- Search scope is optional and consistent in all modes.
- File listing includes assets without indexing them; outline returns deterministic nested headings.
- Expected `kb_patch` mutation/domain errors are visible as meaningful MCP tool errors; unexpected internal failures remain generic and do not expose stack traces or internal details.
- Application services remain reusable by a future transport without depending on MCP/stdin/stdout.
- A process-level integration test launches the real server through the official stdio client transport, completes initialization, lists exactly the ten supported tools, and calls `kb_status`.
- Startup diagnostics do not contaminate stdout, and closing the server's stdin allows the child process to terminate cleanly.
- Secure MCP Tunnel support requires no `tunnel-client` dependency in the automated test suite and no tunnel-specific code in LocalVectorSearchMcp.

## Verification

- Unit-test request validation, enum/operation serialization, scope parsing, conflict errors, and response shapes.
- Integration-test direct tool calls for root read/hash/default pointer, root pagination, empty/front-matter/pre-heading documents, patch operations, file mutations, listing, outline, immediate search visibility, and disabled writes.
- Verify through real `tools/list` metadata/schema that `kb_read` documents `document` as the root and does not require `pointer`, and that `kb_patch.operations[].kind` is a string enum with exactly `replace`, `insert_before`, `insert_after`, and `delete`.
- Through the real stdio client, verify that an expected `kb_patch` mutation/domain failure returns `IsError = true` with actionable text rather than only the SDK's generic invocation error.
- Run the real server as a child process through `StdioClientTransport`; confirm initialization, `tools/list`, all ten tool names, and a successful `kb_status` call.
- Start the real server process, close its stdin, and confirm it exits without unsolicited stdout output.
- Run existing CLI, publish, and packaging verification.
- Manually run the documented OpenAI Secure MCP Tunnel `doctor`, runtime start, ChatGPT discovery, `kb_status`, `kb_search`, and `kb_read` flow when tunnel access is available.
