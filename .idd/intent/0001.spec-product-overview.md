# 0001.spec-product-overview

## Intent

DimonSmart.LocalVectorSearchMcp is a local C#/.NET editable Markdown workbench for one configured workspace. It lets an LLM search large Markdown collections, read focused semantic slices, safely mutate source files through semantic pointers, navigate the workspace, and manage ordinary image assets stored under `images/`.

The server targets `net10.0`, runs on Windows, Linux, and macOS, uses `DimonSmart.LocalVectorSearchMcp` as the root namespace, and exposes application operations through MCP tools and maintenance CLI commands.

## Behavior

Each running server instance belongs to exactly one project, uses one configuration, indexes one allowed root into one project-local SQLite database, and cannot select or access another project's content through its API. Separate projects use separate server instances and indexes.

Markdown files are the source of truth for indexed knowledge. SQLite is a derived search index and is never edited as a substitute for changing a source document. The product parses source Markdown into logical elements with source spans, builds deterministic logical pointers plus canonical public semantic anchors carrying exact-source self and subtree hashes, creates section-bounded search chunks, stores index data in SQLite, and supports FTS5 lexical search, sqlite-vec vector search, and hybrid search through Reciprocal Rank Fusion.

The default search mode is hybrid. Search can optionally be scoped to indexed paths. The server provides MCP operations for reindexing, status, search, focused reads, semantic patching, Markdown file creation/move/deletion, deterministic file listing, Markdown outlines, and production image asset save/list/load/delete operations. Images are ordinary workspace assets under `images/`: they are visible to file listing but are not Markdown sources, search documents, vector chunks, or embedding inputs.

Successful Markdown MCP mutations update the index before the next request observes them. Optional file watching brings external Markdown changes into the index. Image mutations do not trigger Markdown index synchronization.

Core and Infrastructure remain generic workspace components and contain no book-specific concepts. Application services for search, read, mutation, listing, outline, and images do not depend on MCP or stdio classes; MCP tools are thin adapters.

LocalVectorSearchMcp remains a local stdio MCP server. Claude Code and Codex may launch it directly. ChatGPT may access the same stdio MCP surface through OpenAI Secure MCP Tunnel, where the external `tunnel-client` launches or bridges the local child process. The tunnel owns remote connectivity, tunnel authentication, runtime lifecycle, and tunnel health/readiness. LocalVectorSearchMcp does not implement tunnel credentials or a tunnel protocol client.

## Architecture And Patterns

The solution contains:

- `src/DimonSmart.LocalVectorSearchMcp.Core`
- `src/DimonSmart.LocalVectorSearchMcp.Infrastructure`
- `src/DimonSmart.LocalVectorSearchMcp.Server`
- `tests/DimonSmart.LocalVectorSearchMcp.Tests`
- `tests/DimonSmart.LocalVectorSearchMcp.IntegrationTests`

Core contains domain models, DTOs, validation, pure Markdown logic, semantic pointer logic, chunking, ranking, and transport-independent service interfaces. Infrastructure contains SQLite, sqlite-vec, FTS5, YAML loading, protected filesystem access, safe outbound image download, file scanning/watching, embedding HTTP calls, source-aware Markdown parsing, indexing, Markdown mutation, and image asset services. Server is a console application that wires DI, CLI maintenance commands, and MCP stdio hosting.

## Non-goals

The product does not implement direct remote HTTP MCP hosting, application-level authentication for remote MCP, tunnel authentication, a custom tunnel protocol client, multi-user collaboration, Git locking, CRDT or automatic three-way merge, persistent paragraph UUIDs, a WYSIWYG or web editor, PDF/DOCX/OCR ingestion, arbitrary binary upload, image embeddings, image semantic search, image resizing/transcoding/thumbnails, automatic image insertion into Markdown, a media database/catalog, book-specific domain models, or book publishing.

Remote access through an external stdio tunnel is not direct HTTP hosting by LocalVectorSearchMcp and does not change these architecture boundaries.

## Acceptance Criteria

- The solution builds with `dotnet build` and non-manual tests pass with `dotnet test`.
- The server targets `net10.0` and contains no manual MCP protocol implementation.
- A server instance exposes only its configured project; no API operation accepts a knowledge-base selector.
- Search works in lexical, semantic, and hybrid modes, supports optional path scope, and hybrid ranking uses Reciprocal Rank Fusion.
- Indexed content can be read and mutated by semantic pointer with optimistic concurrency.
- Create, patch, move, and delete synchronously reconcile the derived Markdown index.
- Optional watching reconciles external Markdown changes without indexing binary assets or terminating the server on transient failures.
- Workspace files and Markdown outlines can be navigated deterministically.
- Images can be saved to, listed from, loaded from, and deleted within `<knowledgeBase.root>/images/`.
- Image assets are visible through `kb_list_files` as `asset` and never enter the semantic index.
- Existing read/search requests and maintenance CLI commands remain valid.
- The real stdio server can be launched as a child process, complete MCP initialization, list the fourteen supported tools, validate the OpenAI image file-input descriptor, return a real MCP image content block, execute safe tool calls, and terminate cleanly when its stdio owner closes the connection.
- ChatGPT remote access is documented through OpenAI Secure MCP Tunnel without adding a public HTTP listener or application-level tunnel authentication to LocalVectorSearchMcp.

## Verification

- Run `dotnet build` and `dotnet test`.
- Run the Release build and non-manual tests in Linux, Windows, and macOS environments.
- Start the server in MCP stdio mode and inspect all fourteen registered tools.
- Run the process-level stdio integration test through the official MCP client transport and verify `kb_status`, image tool schemas, and `ImageContentBlock` output.
- Exercise create, search, read, patch, move, delete, watcher reconciliation, listing, outline, and image save/list/load/delete against temporary workspaces.
- Verify image operations do not alter the Markdown/search index.
- Run CLI `--reindex`, `--reindex --force`, and `--status` against a test workspace.
- Manually verify the documented OpenAI Secure MCP Tunnel flow when tunnel credentials and a ChatGPT workspace are available.
