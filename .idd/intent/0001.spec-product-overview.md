# 0001.spec-product-overview

## Intent

DimonSmart.LocalVectorSearchMcp is a local C#/.NET editable Markdown workbench for one configured workspace. It lets an LLM search large Markdown collections, read focused semantic slices, safely mutate source files through semantic pointers, navigate the workspace, and immediately search the resulting state.

The server targets `net10.0`, runs on Windows, Linux, and macOS, uses `DimonSmart.LocalVectorSearchMcp` as the root namespace, and exposes application operations through MCP tools and maintenance CLI commands.

## Behavior

Each running server instance belongs to exactly one project, uses one configuration, indexes one allowed root into one project-local SQLite database, and cannot select or access another project's content through its API. Separate projects use separate server instances and indexes.

Markdown files are the source of truth. SQLite is a derived search index and is never edited as a substitute for changing a source document. The product parses source Markdown into logical elements with source spans, builds revision-scoped semantic pointers, creates section-bounded search chunks, stores index data in SQLite, and supports FTS5 lexical search, sqlite-vec vector search, and hybrid search through Reciprocal Rank Fusion.

The default search mode is hybrid. Search can optionally be scoped to indexed paths. The server provides MCP operations for reindexing, status, search, focused reads, semantic patching, Markdown file creation/move/deletion, deterministic file listing, and Markdown outlines. Successful MCP mutations update the index before the next request observes it. Optional file watching brings external Markdown changes into the index.

Core and Infrastructure remain generic Markdown-workspace components and contain no book-specific concepts. Application services for search, read, mutation, listing, and outline do not depend on MCP or stdio classes; MCP tools are thin adapters.

## Architecture And Patterns

The solution contains:

- `src/DimonSmart.LocalVectorSearchMcp.Core`
- `src/DimonSmart.LocalVectorSearchMcp.Infrastructure`
- `src/DimonSmart.LocalVectorSearchMcp.Server`
- `tests/DimonSmart.LocalVectorSearchMcp.Tests`
- `tests/DimonSmart.LocalVectorSearchMcp.IntegrationTests`

Core contains domain models, DTOs, validation, pure Markdown logic, semantic pointer logic, chunking, ranking, and service interfaces. Infrastructure contains SQLite, sqlite-vec, FTS5, YAML loading, protected filesystem access, file scanning/watching, embedding HTTP calls, source-aware Markdown parsing, indexing, and mutation services. Server is a console application that wires DI, CLI maintenance commands, and MCP stdio hosting.

## Non-goals

The product does not implement remote HTTP MCP, authentication, multi-user collaboration, Git locking, CRDT or automatic three-way merge, persistent paragraph UUIDs, a WYSIWYG or web editor, PDF/DOCX/OCR ingestion, image embeddings, binary asset upload/editing, book-specific domain models, or book publishing.

## Acceptance Criteria

- The solution builds with `dotnet build` and non-manual tests pass with `dotnet test`.
- The server targets `net10.0` and contains no manual MCP protocol implementation.
- A server instance exposes only its configured project; no API operation accepts a knowledge-base selector.
- Search works in lexical, semantic, and hybrid modes, supports optional path scope, and hybrid ranking uses Reciprocal Rank Fusion.
- Indexed content can be read and mutated by semantic pointer with optimistic concurrency.
- Create, patch, move, and delete synchronously reconcile the derived index.
- Optional watching reconciles external Markdown changes without indexing binary assets or terminating the server on transient failures.
- Workspace files and Markdown outlines can be navigated deterministically.
- Existing read/search requests and maintenance CLI commands remain valid.

## Verification

- Run `dotnet build` and `dotnet test`.
- Run the Release build and non-manual tests in Linux, Windows, and macOS environments.
- Start the server in MCP stdio mode and inspect registered tools.
- Exercise create, search, read, patch, move, delete, watcher reconciliation, listing, and outline against a temporary workspace.
- Run CLI `--reindex`, `--reindex --force`, and `--status` against a test workspace.
