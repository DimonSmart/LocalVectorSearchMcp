# 0007.spec-markdown-link-graph

## Intent

LocalVectorSearchMcp offers deterministic navigation over explicit Markdown links, independent of lexical and semantic search. Source Markdown is the sole authority; the graph is a disposable SQLite-derived index and never writes to source files. It understands Markdown syntax and file paths, not document types or semantic relationships.

## Behavior

Only configured, included, non-excluded `.md` files are graph source nodes, identified by slash-normalized root-relative paths. An occurrence of a link is a directed edge from its source to a root-relative Markdown target. Every occurrence is stored independently, including repeated links and different fragments; graph navigation returns unique document nodes. Target paths need not exist to preserve incoming broken links.

Supported link forms include standard Markdown inline links, full/collapsed/shortcut reference-style links (each use, not each definition), fragment-only self-links, and links inside heading, list, quotation, formatting and GFM table containers. Markdown AST parsing uses the shared Markdig pipeline. Fenced/inline code, images, HTML links, autolinks, external/schemed URIs, WikiLinks, and YAML frontmatter do not create edges. Only explicit .md destinations are graph targets; there is no extensionless or directory-index inference.

A relative destination is resolved against the source document directory. The destination's query string is ignored for identity but retained in its original form. Percent escaping is decoded once; malformed encodings and encoded separators are rejected. Dot and dot-dot segments are permitted only when the final path stays within the root. Unsafe, absolute or scheme-based destinations cannot be indexed or used to access the filesystem. Both link resolution and read requests obey KnowledgeBasePathGuard, including reparse-point checks. MCP-request paths remain root-relative without traversal. Path identity respects the platform filesystem and retains original case.

Fragment-only links resolve to the source file. Auto-generated heading identifiers follow GitHub-style slugs: formatting removed, Unicode letters preserved, lowercase, whitespace converted to hyphens, and repeated headings suffixed -1, -2, etc. The original fragment is kept as an occurrence property. Fragment checks must never change the document-level identity of a link.

Each occurrence retains normalized source/target paths, original destination, optional fragment, link text, syntax kind, exact source hash and one-based line/column plus zero-based UTF-16 source offset and length. These coordinates refer to the last successfully indexed source revision, not necessarily the live file.

## Resolution states

States are evaluated when reading the graph without reparsing incoming source documents:

- `resolved`: target exists and has a graph node; requested heading slug matches when present.
- `missing_document`: target is absent from the filesystem.
- `target_not_indexed`: target exists in the root but is excluded, awaiting indexing, or indexing failed.
- `anchor_not_found`: target graph node exists but its heading slug is not found.
- `fragment_unverified`: the fragment cannot be reliably checked.

Missing from SQLite is not proof of a broken file. These states are distinct and do not rewrite Markdown.

## Storage and synchronization

Graph tables and a graph schema/revision marker are additive to the existing SQLite database, with no search manifest migration and no forced regeneration of embeddings. Graph access must work without the embedding provider, sqlite-vec extension or vector index; graph initialization never loads the vector extension. Indexed document hashes, occurrence rows and heading slugs are independently maintained.

For one document, replacement of the graph document row, its outgoing occurrences and heading anchors is atomic; failures preserve the last committed version. Unchanged hashes skip reprocessing, but lack of a graph row triggers indexing even if the search index already has that hash. Removing a source removes its outgoing occurrences, not other sources' incoming references. Creating or changing a target can resolve those references without reparsing their sources.

Bulk `kb_reindex` synchronizes the graph separately from chunk/vector processing. `scope=changed` catches absent graph rows, `scope=all` reparses the complete source set. Workspace mutations and the watcher schedule per-file graph reconciliation through the existing serialization gate. Graph synchronization must continue even when embeddings fail. A destructive recreation of the main database must reconstruct the graph from Markdown before it advertises readiness.

Graph queries read a consistent SQLite snapshot, expose a monotonic graph revision and synchronization diagnostics and may lag behind current Markdown. Live `kb_read` keeps reading from disk. Graph failure and pending state must be separate from search synchronization.

## MCP contract

One read-only tool, `kb_links`, accepts a `request` object with:

- `path?: string` (required for ordinary navigation; optional for global `brokenOnly`)
- `direction: outgoing|incoming|both` (default `both`)
- `depth: 1..5` (default 1)
- `includeBroken: boolean` (default false)
- `brokenOnly: boolean` (default false, restricts to `missing_document`, forces outgoing and depth 1)
- `pageSize: 1..500` (default 100)
- `cursor?: string` (opaque, bound to request and graph revision)

Outgoing navigation requires an indexed source. Incoming navigation may target a nonexistent safe .md path. BFS navigates directed or mixed incoming/outgoing edges with cycle protection and minimum-distance nodes. Missing or unresolved outgoing targets are not traversed. `links` includes distinct occurrences and directional metadata; `nodes` deduplicates document paths. Sorting uses distance, paths, source coordinates and stable occurrence ID. Server-side bounds on BFS nodes/edges must result in `truncated=true`, not silent truncation. Pagination must reject a stale revision with `CURSOR_EXPIRED`.

Results include normalized query parameters, nodes, occurrences, status, source hash, discovery distance and direction, graph revision, synchronization state, optional nextCursor and truncated. Controlled errors include INVALID_ARGUMENT, INVALID_PATH, DOCUMENT_NOT_FOUND and LINK_INDEX_NOT_READY. `kb_status.linkGraph` reports ready state, counts, revision, pending work and last graph error. `kb_links` does not require allowWrites.

## Non-goals

Semantic document types or relations, embeddings to infer links, cross-project graphs, WikiLinks/HTML edges, extensionless filename inference, editing or repairing links, external graph databases, document creation, and visualization are excluded.

## Acceptance criteria

- Inline and reference-style occurrences are enumerated correctly across Markdown containers; code and images do not produce false edges.
- Both directions, depth-limited mixed BFS, self-links, cycles, repeated occurrences and sorted output work.
- Unsafe destinations cannot escape the workspace or trigger link-following filesystem reads.
- Missing, excluded, unindexed and wrong-heading targets are diagnosed distinctly.
- Source modification, target creation/deletion, and move are reflected by synchronization without rewriting Markdown or reindexing unaffected sources.
- Hash-based incremental indexing and sqlite-vec/embedding-independent operation are maintained.
- Graph storage is atomic per source; cursors expire upon graph revision change.
- Read-only MCP structured content and `kb_status` expose typed graph data and synchronization state.
- Tests cover significant parsing, security, lifecycle and API invariants.

## Verification

Use temporary Markdown workspaces to exercise parsing, path safety, graph creation/deletion, reindex, BFS and cursor invalidation. Run the multi-OS .NET CI suite and the MCP transport schema checks.
