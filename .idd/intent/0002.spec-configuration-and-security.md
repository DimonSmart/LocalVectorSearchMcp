# 0002.spec-configuration-and-security

## Intent

The server is configured through YAML or server CLI arguments, keeps write and watch capability explicitly disabled by default, and fails with understandable errors when configuration or path access is invalid.

## Related Specifications

- 0001.spec-product-overview.md
- 0004.spec-index-storage-and-search.md
- 0005.spec-mcp-and-cli.md

## Behavior

The server has built-in defaults and does not require a YAML file. A configuration path may be provided with `--config`; when absent, `local-vector-search-mcp.yml` is not loaded implicitly. Effective configuration applies defaults, explicit YAML, then CLI overrides.

Configuration includes server, storage, embedding, chunking, search, and a singular `knowledgeBase` section. `knowledgeBase.root` may be omitted to use the detected project root. `knowledgeBase.allowWrites` and `knowledgeBase.watchFiles` default to `false`. Watch mode requires no write permission, while MCP mutation requires write permission. Legacy top-level `knowledgeBases` is rejected. Existing embedding defaults and remote-endpoint safety rules remain unchanged.

The detected project root is `CLAUDE_PROJECT_DIR` when non-empty, otherwise the current working directory. Root and storage paths use the existing CLI/YAML/default precedence. Relative paths resolve against the project root.

The server validates root, include/exclude filesystem glob patterns, storage, search, chunking, embedding endpoint safety, and the write/watch flags before operations start. The default include is `**/*.md`; the default exclude list is empty. Search scopes use the same glob semantics but filter only already indexed documents and never change the configured source set.

All reads and mutations stay inside the configured root. User paths must be relative, normalized, free of `..` traversal, and resolved with platform path-case semantics. Markdown mutations accept only `.md` paths. Writes must not traverse symbolic links, junctions, or other reparse points that could escape the root; unsafe linked paths are rejected. Create/move never overwrite an existing destination.

## Architecture And Patterns

Configuration records live in Core. YAML loading, CLI parsing, merge, and path resolution live in Infrastructure. A dedicated path guard owns containment and link-safety checks. Invalid configuration raises `ConfigurationException`; unauthorized path access raises `KnowledgeBaseAccessException`.

Embedding API keys, document text, embedding text, and raw vectors are never logged.

## Non-goals

JSON configuration, implicit global filesystem access, writes outside the configured root, and implicit mutation as a side effect of read/search are excluded.

## Acceptance Criteria

- Existing configuration precedence, validation, default embedding settings, configless startup, and CLI overrides remain valid.
- `allowWrites` and `watchFiles` default to `false` and can be enabled explicitly in YAML.
- Disabled mutations return a controlled, understandable error without changing files or the index.
- Include/exclude configuration and search scope use understandable filesystem glob semantics.
- Discovered paths are project-relative with `/` separators and stable ordinal-ignore-case ordering.
- `..`, absolute paths, outside-root paths, and write paths traversing unsafe links/reparse points are rejected.
- Create and move reject non-Markdown targets and existing destinations.
- Loopback embedding endpoints are accepted by default; remote endpoints require explicit opt-in.

## Verification

- Unit-test configuration defaults, YAML loading, enum parsing, glob validation, and path/link security.
- Exercise valid and invalid read and mutation paths against temporary workspaces.
- Start CLI commands with valid and invalid configuration files.
